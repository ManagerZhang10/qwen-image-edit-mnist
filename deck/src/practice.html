04训练 loss · 3000 步训练中每一步 batch 的 loss

每一步的 loss 都在乱跳：看趋势要用固定测试集

为什么乱跳每一步只抽一个 σ：σ < 0.023 或 > 0.957 的步 loss 能到 0.3–2（橙点），中间 σ 的步只有 0.01 左右。
怎么看趋势固定 64 张测试图、固定噪声、固定 5 个 σ，每 50 步量一次：0.043 → 0.020，前 200 步就降了四成。
训练本身没变和前面讲的一样：目标图加噪 → 预测 v = ε − x0 → MSE；多的只是参考图 token 和 t = 0 的前缀。
04训练 loss · 固定测试集，每任务 16 张、固定噪声，每 50 步量一次 · 四个任务混训一个 LoRA

按任务拆开：三个任务小 σ 最难，换数字两头都难

测试 loss 怎么算和训练同一口径：目标图加噪 → 预测 v → 和 ε − x0 算 MSE。只是题目、噪声、σ 都固定，不更新参数，所以曲线不抖。
旋转、反色σ 越大 loss 越低，大 σ 的线降得最多：看不清目标时全靠条件，学会编辑规则就体现在这里。σ = 0.1 几乎不动。
下一个数字σ = 0.9 和 0.1 两条线重合（U 形），3000 步里几乎不降：答案是另一个人写的 n + 1，条件定不下来。
不同任务不能比绝对值同一个模型，σ 两端的 loss 差几十倍；比 loss 先对齐 σ 和任务。
04训练 loss · 第 3000 步的 LoRA · 每组一张测试图 · σ 不到 1 时答案还藏在 x_t 里，模型只是在擦噪声；σ = 1 才是真正的编辑

转 90° 从纯噪声也猜得对，换数字到 σ = 1 就崩了

04训练 loss · 第 3000 步的 LoRA · 固定测试集 16 张 × 4 组噪声 · 恒等式 x0′ − x0 = σ·(v − v′)，所以 v loss = x0 误差 / σ²

两头效应：左头是 1/σ² 放大，右头是看不清目标

拆成两项模型输出 v′ 隐含一个终点猜测 x0′ = x_t − σv′，恒等地有 v loss = x0 误差 × 1/σ²。
左头：分母放大σ 小时 x0 猜得很准（误差约 0.0005），但放大 100 倍。四个任务都有这一头。
右头：看不清目标σ 接近 1 时 x_t 里读不出答案，换数字只能靠自己推，但它没学会（上页 σ = 1 猜出的是一团发黄的影子）：x0 误差涨到 0.1–0.7，压过放大倍数的下降 → U 形。
确定性任务几乎没有右头条件已定下答案，看不清也猜得对，x0 误差始终千分之几，曲线基本只剩左头；σ ≥ 0.95 才微微翘起。
05生图效果 · 测试集每种编辑 16 张 · 分类器是在 MNIST 训练集上训的小网络，测试集准确率 98.8% · 图中是第 3000 步 LoRA 的真实输出

成功率怎么算：先变回正立，再让分类器认数字

为什么先做逆变换分类器只见过黑底白字、正立的数字，转过的 4、反色的 6 它都认不出。所以先按任务把输出变回去：转 90° 的逆时针转回来，转 180° 的再转一次，反色的再反一次。
怎么判认出的数字等于期望数字就算成功：旋转和反色期望原数字，换数字期望 n + 1（9 → 0）。16 张里成功的比例就是这种编辑的成功率。
换数字只看数字，不看写法标准答案是另一个人写的 n + 1，本来就不唯一；画出来是 n + 1 就算对。旋转和反色另算像素 IoU，看是不是逐像素变换。
分类器也会判错98.8% 不是 100%，笔画潦草的输出偶尔会被认错，比如有一张 9 被认成了 8。每种编辑只有 16 张，一张就是 6 个点。
05生图效果 · 每 200 步在测试集上生图一次，分类器判定成败

loss 已经平了，成功率才台阶式跳上去

底模已经会一半第 0 步平均 50%：旋转 90° 75%、180° 62%，但像素 IoU 只有 0.37 / 0.44，数字转对了、形状是重画的。
loss 先降完，成功率后跳测试集 loss 第 50 步已完成全程降幅的 63%，第 200 步 79%，之后几乎是平的。成功率却在 200–600 步才跳：180° 第 200 步到 100%，90° 第 400 步，反色第 600 步到 94%。
先变差再变好第 200 步反色从 38% 掉到 19%：LoRA 先学会「照着参考图复制」，抹掉了底模自由发挥时碰巧对的那部分。
所以要看指标loss 平了不等于没在学，也不等于学会了；训练时一定要带验证集和任务指标。
05生图效果 · 训练前后 · 同一批测试输入 · ✓ / ✗ 为分类器判定

同一批输入：从「重画一个」变成逐像素变换

旋转底模会转，但会把手写体改成印刷体；180° 偶尔出灰底锯齿。800 步后和标准答案几乎重合，IoU 0.94 / 0.97。
反色底模基本原样输出（IoU 0.01）；训完后白底黑字、笔画位置不变，IoU 0.99。
下一个数字底模把「9 变成 0」当文字画出来；训练后变成像样的手写体，但数字经常不对。
checkpoint 选哪个第 1000 步起平均成功率就稳在 75–77%，最后一步和最好的一样，用 3000 步。
05生图效果 · 第 3000 步的 LoRA · 测试集

规则学得会，语义学不会：3000 步仍不会换数字

学得最快：180°200 步到 100%。每个像素都有唯一确定的去处，模型只要学会一个固定的搬运规则。
反色、90° 紧随其后400–600 步。它们也是逐像素的确定性变换；90° 的难点在于底模原本的「重画」习惯要被改掉。
「下一个数字」目标是另一个人写的 n + 1，同一张输入的答案本身是随机的：loss 只降了三分之一，成功率一直在 0–19%。
要学会该怎么办更多数据、更长训练，或者让目标确定下来（比如固定一套字体）。2000 对、LoRA、3000 步不够。
05生图效果 · 推理设置 · 第 3000 步的 LoRA，同一批 64 个输入和噪声（每种编辑 16 个），只改 CFG · 负向提示词为空

调 CFG：只帮「换数字」6% → 31%，但慢一倍

公式v = v_neg + s · (v_cond − v_neg)：v_cond 带指令和参考图，v_neg 用空负向提示词，每步两次前向。s = 1 就是 v_cond（2.1 默认），s > 1 沿「条件带来的差」多走几倍；2.1 不缩范数。
确定的三个任务已经饱和转 90° 和 180° 都是 100%，反色 94%，CFG 调到多少都不变，IoU 也一直在 0.94–0.99。
换数字：6% → 19% → 31% → 31%对应 CFG 1 / 2 / 4 / 7；照抄原数字的比例从 12% 降到 0。每种编辑只有 16 个样本，差一个样本就是 6 个点。
代价每张从 2.3 s 翻到 4.6 s。彩色伪影反而从 1.6 降到 0.7，CFG 7 也没冒色块。
05生图效果 · 推理设置 · 第 3000 步的 LoRA，同一批 64 个输入和噪声（每种编辑 16 个）· 40 步，关掉动态 shift 改成固定值

调 σ 分布（shift）：40 步下几乎没影响

怎么改的关掉动态 shift，改成固定的 shift = s，最小 σ 仍停在 0.02。默认的动态 shift 在 512² 下约等于 1.71。
结果shift 1 / 默认 / 3 / 6：成功率 75% / 75% / 77% / 77%。差别全在「换数字」的 1 到 2 个样本，另外三个任务一个都没变。
为什么没影响40 步足够密，σ 怎么分配都能把轨迹走完；shift 的作用要在步数少、分辨率高时才明显。
没跑的组合少步数 × 不同 shift 这次没测，不能外推。
05生图效果 · 推理设置 · 第 3000 步的 LoRA，同一批 64 个输入和噪声 · 加载 LoRA 后按比例缩放它的输出

调 LoRA 强度：0 就是原模型，0.5 已经够用

0 = 原模型强度 0 的输出和底模逐像素相同：LoRA 只是加在原权重上的一个增量，关掉就回到原样。
0.5 就学会了成功率 47% → 81%：两种旋转 100%，反色 94%（底模一次都没做对），紫绿色块全部消失。
调大反而伤语义强度 0.5 / 1.0 / 1.5 时「下一个数字」31% / 12% / 0%，其余三个任务不变：过强的 LoRA 把「照着参考图变换」推过了头。
右下小图：彩色伪影MNIST 只有黑白灰，出现颜色就是画坏了。把每个像素 RGB 三个通道的最大差取平均：强度 0 时反色 60、转 180° 33、换数字 10（底模冒出紫绿色块，见 180° 那格），转 90° 本来就干净；0.5 起四个任务都降到 2 以下。
05生图效果 · 推理设置 · 第 3000 步的 LoRA，同一批 64 个输入和噪声（每种编辑 16 个）· LoRA 强度 1.0，只改采样步数

调采样步数：答案唯一的 2 步就够，换数字糊成平均图

2 步 = 40 步两种旋转 100%、反色 94%，从 2 步到 40 步一个不差；每张 0.3 s 对 2.3 s，快 8 倍。
「下一个数字」少步是一团糊目标是另一个人写的 n + 1，可能的答案很多；少步时每一步落在这些答案的平均上，出来是一团模糊的影子，16 步起才画成一个具体的 9。
右下小图：笔画亮度不用分类器，直接量像素：取每张图最亮那 1% 像素的亮度（反色先反回来），按任务分开画。发灰的只有「换数字」：2 步 43%、4 步 71%、8 步起 97%；另外三个任务 2 步就接近 100%。
所以少步靠什么让条件分布变窄（微调到具体任务）或专门蒸馏；只改采样器救不了答案本来就多的任务。
